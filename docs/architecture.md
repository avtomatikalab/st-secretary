# Архитектура

Согласована с организаторами 28.09.2026. Здесь — целевая картина; что уже сделано, см. [roadmap.md](roadmap.md).

## Условия, под которые строится система

- Соревнования муниципального и краевого уровня; приоритет — ПСР (дистанция – комбинированная)
  и спелео, далее горные, пешеходные дистанции, северная ходьба.
- Интернет на месте бывает, бывает не у всех операторов, а бывает, что его нет совсем.
  VPN у многих судей нет.
- Пользователи — судьи и секретари, уверенно работают в Excel, многим больше 50 лет.
  Система должна упрощать работу, а не добавлять новую.
- Ноутбук секретариата, принтер, генератор. У судей — смартфоны Android и iPhone.
- Электронная отметка SPORTident есть не всегда: её поддержка нужна, но работа без неё обязательна.

## Три узла

```
 Телефоны судей (веб-приложение, работает без связи)
     │  записи хранятся в телефоне и уходят, когда появится канал:
     │  интернет → облако  |  Wi-Fi ноутбука  |  QR-код (крайний случай)
     ▼
 Ноутбук секретариата  ◄──── синхронизация, когда есть интернет ────►  Облако (сервер в РФ)
  • главная копия данных соревнования                                   • онлайн-табло
  • расчёт результатов, документы, печать                               • приём данных от судей
  • местное табло и приём данных по своей Wi-Fi                          • архив
  • работает полностью без интернета                                    • донаты (самозанятый)
```

1. **Ноутбук — главный.** Вся база соревнования, расчёты, документы и печать — на нём, без
   интернета. Он же раздаёт свою сеть Wi-Fi: через неё судьи сдают данные, а все на поляне видят
   местное табло.
2. **Облако** — российский хостинг, открывается без VPN у всех операторов. Онлайн-табло, приём
   данных от судей, архив. Не зависит от Google, Telegram и других сервисов, недоступных без VPN.
3. **Телефоны судей** — страница по QR-коду, «на главный экран», без магазинов приложений.
   Записи копятся в телефоне и уходят любым доступным путём. Бумажный протокол ведётся параллельно.

## Данные

- **Записи судей только добавляются** (журнал событий). Исправление — новая запись со ссылкой
  на прежнюю. Слияние данных с разных устройств не даёт конфликтов, для протестов виден полный
  след: кто, что и когда записал.
- **Точная арифметика.** Время хранится в секундах, баллы и проценты — точными дробями
  (`fractions.Fraction`); округление только при выводе в документ.
- **Персональные данные — по минимуму.** В облако уходят ФИО, команда и результат. Даты рождения,
  паспортные данные, реквизиты договоров остаются на ноутбуке. Хранение в РФ (152-ФЗ).

## Дисциплины — профили одного движка

| Дисциплина | Результат | Справочник нарушений | Места и снятия |
|---|---|---|---|
| ПСР | Сумма баллов этапов: ТШ + ВШ − премии | Табл. 4 ч. 4 + штрафы этапов из Условий | Наименьшая сумма; фактический класс (без этапов с МШ) |
| Спелео | Время − отсечки + баллы × 15/30 с | Приложение 2 к ч. 8 (дробные баллы) | Со снятиями — после прошедших полностью |
| Горные | Баллы: время (2 или 4 балла/мин) + техника + тактика | Табл. 6, 7, тактическая заявка | Меньше снятий, затем меньше баллов; при равенстве — стартовавший раньше |
| Пешеходные | Время + штрафное время или баллы × 15/30 с | Табл. 11 ч. 7 | Снятие с дистанции или ОКВ за каждое снятие |
| Северная ходьба | Время + баллы × 15 с или остановки 15/30/60 с | Табл. 4 разд. 4 | 5 замечаний от ≥2 судей = предупреждение; красная карточка |

Общее для всех: места с равенством по п. 8.18 раздела 3 Правил, ранг и нормативы по выбранной
редакции норм, условие ЕВСК о числе участников.

## Справочники

Хранятся в `src/st_secretary/reference/data/*.toml`, у каждого указан первоисточник; при наличии
реальных файлов тесты сверяют их с первоисточником автоматически.

- `vrvs.toml` — коды и наименования дисциплин по ВРВС.
- `norms/<редакция>.toml` — разрядные нормы; в соревновании редакция выбирается явно,
  дополнительные нормы из Положения задаются отдельной таблицей соревнования (этап 1).
- `admission.toml` — возраст, возрастные группы, минимальный разряд по классам.

## Технологии

- Python 3.12+, без внешних зависимостей в ядре; `xlrd` — только для чтения старых .xls.
- Документы — шаблоны Word/Excel, которые секретари могут править сами (этап 1).
- Интерфейс — страница в браузере от сервера на ноутбуке (FastAPI + Jinja, без сборки фронтенда и
  загрузок из интернета); запуск двойным щелчком. Цель — установка одним файлом, без установки Python.
- ИИ — необязательные помощники (разбор заявок из почты, подсказка судье пункта таблицы штрафов),
  провайдер сменный и доступный из РФ. В расчётах ИИ не участвует.
