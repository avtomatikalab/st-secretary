## 1. Первые полчаса

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync --extra xls                 # библиотеки (xls — чтение старых книг Excel)
uv run pytest                       # ~470 тестов, ~20 секунд
uv run ruff check src tests tools   # проверка стиля (правила — в pyproject.toml)
uv run st-secretary web --docs ./проба-документы
```

Последняя команда запускает программу: папка соревнований — `данные/` в текущей папке (она в `.gitignore`),
сканы и личные данные — в `./проба-документы` (по умолчанию это папка в профиле пользователя, где могут лежать
настоящие документы, — при разработке лучше указывать свою). Откроется браузер на http://127.0.0.1:8765. На
главной кнопка **«Учебное соревнование»** создаёт соревнование с выдуманными командами, этапами и специально
оставленными ошибками в заявках — на нём удобно пройти все шаги.

Перед коммитом — тесты и ruff. После отправки в `main` GitHub сам гоняет тесты на Windows, macOS и Linux и
собирает переносные архивы (`.github/workflows/tests.yml`); итог — `gh run list --limit 3`.

Три правила проекта, которые нельзя нарушать:
- **реальные данные** (ФИО, даты рождения, паспорта, сканы, протоколы с фамилиями) **не попадают в репозиторий**:
  тесты — на выдуманных людях; сверка с настоящими протоколами — только через `ST_REF_DATA` (раздел 11);
- **тексты для секретаря — по-русски и простым языком**, без технических слов; каждое сообщение объясняет, что
  будет с данными. Коммиты, комментарии и документация — тоже по-русски;
- **программа работает без интернета** и на трёх системах: никаких загрузок с CDN, путей с `\`, команд только
  одной ОС.

## 2. Общая картина

СТ-Секретарь — веб-приложение, которое работает **на ноутбуке секретариата**: Python-сервер (FastAPI +
Jinja2) и страницы в обычном браузере. Базы данных нет — каждое соревнование это папка с файлами Excel и JSON,
которую можно открыть в Проводнике и скопировать на флешку.

```
                ┌───────────────────────── ноутбук секретариата ─────────────────────────┐
                │                                                                         │
  секретарь ──► │ браузер ──► http://127.0.0.1:8765 ──► основной сервер (web/app.py)      │
                │                (только этот компьютер)      │  страницы web/pages/*.py   │
                │                                             │  расчёты — ядро            │
                │                                             ▼                            │
                │                              папка «данные» (Excel + JSON),              │
                │                              «документы участников» (сканы, паспорта)    │
                │                                             ▲                            │
  телефоны ───► │ Wi-Fi ноутбука ──► http://<адрес>:8780 ──► сервер табло (web/board.py)  │
  судей и       │                (включается кнопкой)          табло — только чтение;     │
  зрителей      │                                              /j/<код> — страница судьи  │
                └─────────────────────────────────────────────────────────────────────────┘
                                      │ раз в 4 часа (если есть интернет)
                                      ▼
                    api.github.com — есть ли новый выпуск (updates.py, console.py)
```

- **Основной сервер** слушает только `127.0.0.1`: в нём заявки с датами рождения, паспорта, договоры.
- **Сервер табло** — отдельное маленькое приложение в том же процессе (поток), слушает все адреса ноутбука.
  Отдаёт только табло (результаты соревнований, где секретарь включил табло) и страницы судей этапов по
  случайному коду ссылки. Запускается кнопкой в программе.
- **Телефон судьи** держит записи у себя (`localStorage`) и отправляет их на ноутбук, когда есть связь.
- Облачного сервера пока нет (он в планах — architecture.md).

Процесс один: `st-secretary web` → `cli.cmd_web` → `uvicorn` с приложением из `web/app.create_app`. Окно
терминала — это и есть программа: закрыли окно — программа выключилась (это штатно и пишется в журнал).

## 3. Слои кода и правило зависимостей

```
src/st_secretary/
  ядро ─ competition, preapp, commission, start_list, psr_run, time_run, stage_time, judge_sync, festival, …
   │       чистые функции и классы данных: на входе — объекты и словари, на выходе — объекты и замечания (Issue)
   ├─ reference/      справочники (TOML/JSON рядом с кодом): ВРВС, нормы, допуск, таблицы штрафов, баллы судей
   ├─ disciplines/    правила мест конкретных дисциплин (ПСР, спелео)
   ├─ importers/      чтение файлов: карточка, предзаявки, книги СЕКРЕТАРЬ_ST, SI Reader
   ├─ exporters/      запись документов: протоколы, дипломы, договоры, табель, выписки (Excel, Word)
   └─ web/            всё, что связано с браузером: сервер, страницы, хранение папок, шаблоны, JS, CSS
tools/                сборка переносных архивов, инструкция со снимками, импорт справочников, сверки
tests/                pytest; на каждый модуль ядра — свой файл; страницы — tests/test_web.py
```

**Правило: ядро не знает о вебе.** Ни один модуль вне `web/` не импортирует `fastapi`, `starlette`, `jinja2`
или `st_secretary.web` (исключение — `cli.py`, который запускает сервер, и то внутри функции). Поэтому расчёты
тестируются без сервера, а их можно вызвать из командной строки или скрипта. Новый расчёт — в ядро; страница
только собирает данные, вызывает ядро и показывает результат.

Хранение (`web/store.py`) формально лежит в `web/`, но от веба не зависит: это работа с папками и JSON.

## 4. Путь данных: от карточки до наградных

Порядок совпадает с меню программы (`web/steps.py`) и с работой секретариата:

| Шаг | Что вводит человек | Что делает код | Где |
|---|---|---|---|
| Карточка | название, даты, ГСК, зачёты | `Competition` — реквизиты для всех документов; проверка `Competition.check()` | `competition.py`, `importers/card_xlsx.py`, `web/forms.py` |
| Предзаявки | файлы Excel команд | чтение → чистка ФИО, дат, разрядов → сверка с карточкой → `PreappResult` (команды, участники, замечания) | `importers/preapp_xlsx.py`, `forms.py`, `preapp.py`, `textclean.py`, `admission.py` |
| Отметки секретаря | «проверено», статус заявки | замечания с учётом отметок, статус «Исправить / Проверить / Проверено» | `web/review.py` |
| Комиссия по допуску | документы, решения, взносы, номера | `TeamCheck` / `PersonCheck` — кто допущен и почему; делегации, фестиваль | `commission.py`, `equipment.py`, `festival.py` |
| Кто стартует | — | команды / связки / спортсмены зачёта (`TeamInput`) по колонкам участия в заявке | `units.py` |
| Жеребьёвка | способ, время старта, порядок | порядок старта, группы, время; стартовый протокол | `start_list.py`, `exporters/start_protocol.py` |
| Телефоны судей | (судьи на этапах) | записи судей → журнал этапа → клетки таблицы, расхождения | `judge_sync.py`, `stage_time.py`, `penalties.py` |
| Результаты | баллы и время этапов, протесты | места, ранг, процент, разряды → протоколы | `psr_run.py`, `time_run.py`, `ranking.py`, `rank.py`, `norms.py`, `exporters/results_protocol.py` |
| Награждение и итоги | оценки судей, тексты отчёта | дипломы, наклейки, справки, выписки, отчёт | `results.py`, `exporters/awards.py`, `exporters/final.py`, `exporters/judges.py` |
| Договоры | дни, ставки, личные данные | табель, договоры, акты (из одних и тех же отметок) | `staff.py`, `exporters/contracts.py`, `money.py`, `names.py` |
| Сверка | готовые документы | расхождения дат, кодов, ФИО, сумм между документами | `verify.py` |

Главная цепочка в коде (то, что пересчитывается при открытии страницы результатов):

```
CompFolder.load()                         карточка Excel → Competition
Store.preapps(f, comp)                    файлы заявок → read_preapplication → preapp.process → PreappResult
Store.review(f, comp)                     + отметки секретаря (web/review.apply_marks)
commission(f, comp)  [web/pages/admission.py]   → commission.evaluate → [TeamCheck]
zachet_inputs(f, comp, z) [web/pages/results.py] → units.zachet_units → [TeamInput]
run_ctx(f, comp, z)  [web/pages/results.py]     → psr_run.compute или time_run.compute → ZachetRun
                                                   (+ judge_sync.judge_issues — расхождения с телефонами)
```

Ничего из этого не хранится готовым: результаты, допуск и замечания **считаются заново** из исходных файлов
при каждом открытии страницы. Хранятся только ввод человека и присланное судьями. Дорогое место — чтение
заявок; оно запоминается (`Store._preapp_cache`), пока не изменились файлы заявок, карточка и свои формы.

## 5. Где что хранится

### Папка «данные» — соревнования

Путь задаётся `--data` (по умолчанию `данные` рядом с программой). Одна папка — одно соревнование; имя —
`ГГГГ-ММ-ДД Название`, чтобы в Проводнике шли по датам. Константы имён файлов — в начале `web/store.py`.

```
данные/
  Фестивали.json                         фестивали: какие соревнования вместе, общая ГСК, режимы (festival.py)
  2025-09-20 Чемпионат г. Красноярска…/
    Карточка_соревнования.xlsx           карточка — ИСТОЧНИК ПРАВДЫ; её можно править и в Excel
    Предзаявки/                          файлы заявок команд (как прислали или исправленные в программе)
      Прежние версии/                    файл до исправления или замены — с датой в имени
      Убранные/                          заявки, убранные из обработки (не удаляются)
      Заявки делегаций (исходные)/       заявка делегации до деления на команды (свои формы)
    Отметки_предзаявок.json              статусы заявок и «проверено» у замечаний (web/review.py)
    Сводка_предзаявок.xlsx               по кнопке — для СЕКРЕТАРЬ_ST
    Комиссия_по_допуску.json             документы, решения, номера, взносы, перезаявки, делегации (commission.py)
    Комиссия_по_допуску.xlsx             протокол комиссии и ведомость взносов — по кнопке
    Проверка_снаряжения.json             перечень и отметки снаряжения (equipment.py)
    Результаты_дистанции.json            этапы, баллы, время, жеребьёвка, записи судей, ссылки судей, табло
    Протоколы/                           предварительные и официальные протоколы (Excel)
    Итоги.json                           места по зачётам, оценки судей, тексты отчёта (results.py)
    Документы по итогам/                 дипломы, наклейки, справки, выписки, отчёт
    Договоры_и_табель.json               бригада, дни, ставки, заказчик — без паспортов (staff.py)
    Шаблон договора.docx                 свой шаблон договора, если есть
Резервные копии/                         zip папок соревнований — рядом с «данными» (backup.py)
Журнал/                                  журнал программы — рядом с «данными» (journal.py)
```

### Папка «документы участников» — только этот компьютер

Путь — `--docs` (по умолчанию `~/СТ-Секретарь — документы участников`). Сюда нарочно вынесено всё, где есть
паспортные данные и сканы: папку «данные» часто держат в облаке или передают на флешке, а эту — нет.

```
СТ-Секретарь — документы участников/
  Судьи и персонал — личные данные.json  паспорт, ИНН, СНИЛС, счёт, телефон — общий для всех соревнований
  Свои формы заявок.json                 свои формы предзаявок (forms.py)
  Свои значения (неофициальные).json     запомненные группы, названия зачётов, дисциплины (решение 038)
  Формы заявок — образцы/                образцы, пока секретарь настраивает форму (удаляются после сохранения)
  <папка соревнования>/
    <заявка команды без расширения>/     сканы документов команды; внутри — «Убранные»
    Договоры и табель/                   договоры с актами и табель (в них паспорта)
    Делегация <территория · представитель>/<ФИО дата рождения>/   сканы людей делегации
  Фестиваль <название>/                  то же для фестиваля: общие сканы делегаций, общий договор
```

### Результаты_дистанции.json — самый «живой» файл

В него пишут и секретарь, и телефоны судей одновременно, поэтому **запись — только под `cx.run_lock`**
(см. `shared.save_zachet` в `web/shared.py`). Устройство:

```
{
  "zachety": {
    "<ключ зачёта>": {                  Zachet.key: zid или «группа_класс», например «М/Ж_3»
      "stages": [{"id", "tour", "name", "max", "tsh", "vsh", "kv", "nv", "vsh_n", "vsh_m"}],
      "teams": {"<файл заявки>[#связка:…|#…]": {"points": {этап: "12"}, "status", "note", "start",
                "finish", "cutoffs", "chip", "unremoved", …}},
      "draw": {"method", "order", "seed", "at", "first", "interval", "times", "groups", "published", …},
      "judge": {"<этап>": {"<файл>": запись судьи — что прислал телефон, когда, кто}},
      "judge_who": {"<этап>": {"<телефон-устройство>": {"fio", "phone", "last"}}},
      "pen_map": {...}, "penalty_table", "penalty_custom", "pen_jargon",   таблица штрафов зачёта
      "spp", "kv", "system", "tie", "wait_cut", "vsh_round", "removed_order", "protocol_codes",   настройки
      "published": {...}, "official": {...}, "protests": [...]            протоколы и протесты
    }
  },
  "judge_links": {"<код ссылки>": {"z": ключ зачёта, "stage": id этапа, "created"}},
  "board": {"on": true}
}
```

Ключ команды — **имя файла заявки** (`Сосны.xlsx`). У связки и спортсмена — `файл#связка:см` и
`файл#<ключ ФИО>` (`units.py`), у второй группы команды — `файл#группа:2`. Если файл заявки переименовать,
данные команды «потеряются» — поэтому `CompFolder.rename_marks` переносит отметки при `.xls → .xlsx`.

### Правила записи (соблюдать в новом коде)

- **Сначала во временный файл, потом `os.replace`** — оборванная запись не портит данные
  (`store.save_json`; в папке соревнования — `CompFolder.write_json`). Временные файлы начинаются с `~` или `~$` —
  их не видят списки заявок.
- **Ничего не удалять**: убранная заявка → «Убранные», заменённая → «Прежние версии» с датой.
- **Файл открыт в Excel** → `PermissionError`: страница говорит «закройте файл в Excel и нажмите ещё раз», данные
  на странице не теряются.
- **Имя файла от пользователя** — только через `safe_name` и `Path(name).name` (защита от `..` и запрещённых
  в Windows знаков). Файл по имени из адреса — только из своей папки (`CompFolder.preapp_path`, `Store.team_doc`).
- **Старые файлы должны читаться**: схем и миграций нет, новые поля читаются через `.get(…, по умолчанию)`.
  Добавили поле — убедитесь, что соревнование, сохранённое прежней версией, открывается.
- **Карточка — Excel**, чтобы секретарь мог править её и вне программы. Перед сохранением формы сверяется
  метка версии файла (`CompFolder.version`, время изменения): если файл успели поправить в Excel — конфликт,
  а не тихая перезапись.

## 6. Карта файлов

### Ядро — `src/st_secretary/`

| Файл | За что отвечает |
|---|---|
| `__init__.py`, `__main__.py` | версия программы; `python -m st_secretary` (так запускается переносная версия) |
| `cli.py` | командная строка: `web`, `card-template`, `card-check`, `preapp`; запуск сервера (`cmd_web`), перезапуск после обновления |
| `console.py` | окно программы: версия, проверка обновлений раз в 4 часа, «обновить сейчас?» |
| `journal.py` | журнал в файл, метка «работает» (поймать неожиданное закрытие), архив журнала |
| `updates.py` | выпуски на GitHub, скачивание со сверкой sha256, распаковка `program.new`; обновление исходников через git |
| `backup.py` | резервные копии (zip папки соревнования), автокопии при запуске, восстановление без затирания |
| `system.py` | слова, зависящие от ОС (имя файла запуска, «окно» или «терминал») |

## 7. Программа в браузере: как устроена страница

### Сборка приложения

`create_app(data_dir, opener, shutdown, docs_dir, board_host)` в `web/app.py`:
1. создаёт `Store` и кладёт в `app.state` всё, что нужно страницам и тестам: `store`, `opener` (чем открывать
   файлы — в тестах подменяется), `clock` (часы — в тестах подменяются, чтобы проверить «час на протесты»),
   `shutdown`, `installer`, `journal`;
2. настраивает Jinja2: фильтры (`d` — дата, `team_anchor`, `row_place`) и глобальные переменные (уровни
   замечаний, шаги меню, `fix_url`, версия для адресов CSS/JS);
3. собирает общий контекст страниц `cx` и по очереди вызывает `register(app, cx)` у каждого модуля
   `web/pages/`;
4. ставит обработчики ошибок: 404, «нечем открыть файл» (`CannotOpen`) и всё остальное — страница «Что-то пошло
   не так» с текстом ошибки (и запись в журнал).

### Общий контекст `cx`

Что `app.py` кладёт в `cx` для всех страниц:

| Имя | Что это |
|---|---|
| `cx.store` | `Store` |
| `cx.templates` | шаблоны (для частей страницы, которые отдаются в JSON) |
| `cx.page(request, "шаблон.html", **ctx)` | ответ-страница; сама добавляет сообщение «Готово…» и флаги каркаса |
| `cx.folder(cid)` | `CompFolder` или 404 |
| `cx.comp_ctx(f)` | `{"folder", "comp", "card_errors", "base", "festival"}` — нужно каркасу `base.html` |
| `cx.run_lock` | замок на `Результаты_дистанции.json` |

Больше в `cx` ничего нет. **Логика, нужная нескольким страницам, — в `web/shared.py`**, страницы импортируют её
явно (`from st_secretary.web.shared import commission, need_comp`). Функциям, которым нужно хранилище, оно
передаётся первым аргументом, записи в «Результаты_дистанции.json» — замок:

| Функция | Что делает |
|---|---|
| `need_comp(f)`, `need_file(f, имя)`, `need_zachet(comp, код)` | карточка без ошибок (иначе 409), файл заявки, зачёт (иначе 404) |
| `team_url(f, файл)`, `back_to(request, f, откуда, иначе)` | адрес заявки команды; «вернуться туда, откуда нажали» |
| `commission(store, f, comp)` | отметки комиссии и состояние допуска каждой заявки |
| `festival_members(store, фестиваль)`, `adm_totals(команды)`, `doc_list(store, f, файл)` | соревнования фестиваля с допуском; плитки комиссии; сканы команды |
| `zachet_inputs(store, f, comp, z)`, `run_ctx(store, f, comp, z)` | кто выступает в зачёте; расчёт зачёта |
| `save_zachet(run_lock, f, код, update)` | изменить данные зачёта под замком |
| `protocol_state(zdata, run, сейчас)`, `PROTEST_HOUR` | публикация протокола и час на протесты |
| `start_ctx(store, f, comp, z)`, `start_default(f, comp)` | стартовый протокол зачёта; день и время старта по умолчанию |

### Жизненный цикл запроса

```
GET  /c/{cid}/admission
     f = folder(cid); ctx = comp_ctx(f); …вызовы ядра…; return page(request, "admission.html", **ctx, …)

POST /c/{cid}/admission/team          (форма)
     читает форму → меняет JSON соревнования → redirect(with_done(адрес, "adm_saved"))   ← код 303
GET  /c/{cid}/admission?done=adm_saved
     page() → flash(request) превращает done=… в зелёное или красное сообщение над страницей
```

- После POST — всегда переадресация (303) с `?done=код`; текст сообщения — словарь в `web/common.flash`.
  Новое действие → новый код и текст там же.
- Ошибка ввода — страница рисуется заново из того, что ввёл человек (код 422), ошибки — у полей.
- **Автосохранение** (комиссия, баллы этапов): `app.js` отправляет ту же форму `fetch` с заголовком
  `X-Autosave: 1`; страница отвечает JSON с готовым HTML обновлённого блока (`_admission_team.html`,
  `_results_table.html`…), JS заменяет блок. Без JS те же формы работают кнопкой «Сохранить».

### Замечания и кнопка «Исправить»

Любая проверка возвращает список `Issue` (`issues.py`). Чтобы у замечания была кнопка «Исправить», заполните
`target` — строку вида `вид:подробности`; `web/common.fix_url` переводит её в адрес страницы и поле, `app.js`
на той странице раскрывает раздел, ставит курсор и подсвечивает поле (`?focus=…`). Виды target перечислены в
комментарии к `Issue.target` и в `fix_url`. Новый вид — добавьте его в `fix_url` и в тест
`tests/test_fix_links.py` (там проверен адрес для каждого вида).

### JavaScript (`web/static/app.js`)

Один файл без библиотек и без сборки, одна функция-обёртка; блоки поведения подключаются по атрибутам в
разметке, каждый блок начинается комментарием `// --- …`. Основные атрибуты:

| Атрибут | Поведение |
|---|---|
| `form[data-guard]` | предупредить, если уходят со страницы с несохранёнными изменениями |
| `[data-dropzone]` | перетащить файлы — и сразу отправить |
| `form[data-confirm]`, `button[data-confirm]` | подтверждение перед действием |
| `form[data-busy]` | «идёт работа» на долгих действиях |
| `[role=tablist]` | вкладки |
| `[data-team-filter]`, `[data-filter]` | фильтры команд и замечаний |
| `form[data-points]` | баллы этапов: автосохранение, Enter — вниз, как в Excel |
| `table[data-reorder]` | перетаскивание порядка старта (мышь, палец, стрелки) |
| `[data-schedule]` | наглядное расписание стартов |
| `[data-doc-viewer]` | просмотр сканов: листать, повернуть, увеличить |
| `textarea[data-autosize]` | поле растёт по тексту |

Страница судьи `judge.html` — отдельный мир: свои стили и скрипт внутри шаблона (раздел 8).

`tests/test_fix_links.py` прогоняет JS через `node --check`: синтаксическая ошибка в `app.js` ломает все страницы
разом — такое однажды было.

## 8. Телефоны судей и табло

### Ссылка этапа

Секретарь на странице «Телефоны судей этапов» выдаёт ссылку этапу: `judge_sync.issue_token` записывает случайный
код в `judge_links` файла результатов. Ссылка `http://<адрес ноутбука>:8780/j/<код>` (и QR-код) открывает
страницу судьи только этого этапа; новая ссылка отменяет прежнюю. Без кода ничего изменить нельзя.

### Страница судьи (`web/templates/judge.html`)

Данные страницы (`judge_page` в `web/pages/board.py`): команды зачёта в порядке старта, этап (КВ, НВ, ВШ),
таблица штрафов, телефоны других судей, то, что ноутбук уже принял, адрес отправки. Они вставлены в страницу
как JSON (`<script type="application/json" id="data">`).

На телефоне в `localStorage`:
- `st-judge:<код>` — `{records: {файл: запись}, sent: {файл: updated}, lastSent, contacts}`;
- `st-judge-me` — кто судит (ФИО, телефон) — один раз на телефоне, для всех этапов;
- `st-judge-device` — случайный номер устройства (отличить два телефона на одном этапе).

Каждое изменение записи ставит `updated` (мс) и вызывает `sync()`: неотправленные записи (`sent < updated`)
уходят POST-ом на `/j/<код>/sync` как `{device, judge, records}`. Ответ `ok` — записи отмечаются отправленными
**в той версии, что ушла** (если судья успел поменять запись во время запроса, она уйдёт ещё раз). Нет связи —
записи ждут в телефоне. Сервис-воркера нет: страница работает без связи, пока открыта вкладка; записи
сохраняются в любом случае.

На ноутбуке секретаря та же страница открывается по `/c/{cid}/judges/phone/<код>` — посмотреть, что видит судья,
или внести за него (сел телефон).

### Слияние (`judge_sync.merge`)

Под `run_lock`: запись судьи → журнал этапа (`judge[этап][файл]`: что, когда, с какого устройства, кто) →
клетка таблицы баллов, **если клетка пустая или в ней то, что этот этап присылал раньше**. Если секретарь вписал
своё (например, после протеста), таблица не меняется, а на странице результатов появляется расхождение
(`judge_issues`). Более старая версия записи с того же устройства не затирает новую. Подробности для ПСР с НВ/КВ
(итог этапа = техштраф + ВШ считает программа) — `stage_time.refresh`; отсечки — `merge_cutoffs`.

### Табло

`web/board.create_board_app` получает от `web/pages/board.py` функции (`boards`, `board`, `judge_page`,
`judge_sync`) — сервер табло сам ничего не читает с диска и не видит заявок. Табло — страница без скриптов,
обновляется сама раз в 30 секунд. `BoardServer` запускает его в потоке на порту 8780 (или следующем свободном).

## 9. Расчёт результатов

- **Точная арифметика.** Баллы и время — `fractions.Fraction`, время — в секундах. Округление — только при выводе
  (`psr_run.points_text`, `time_run.clock_text`). Не используйте `float` в расчётах.
- **Два расчёта зачёта** с общими классами результата (`psr_run.TeamResult`, `ZachetRun`):
  - `psr_run.compute` — баллы по этапам (ПСР): сумма, туры, места, ранг, процент, разряд, фактический класс;
  - `time_run.compute` — старт, финиш, отсечки, штрафные баллы × эквивалент (спелео, пешеходные, северная
    ходьба, горные — `time_run.profile`). Какой нужен — решает `time_run.is_time_discipline(z)`.
- **Места** — `ranking.assign_places` (равенство, «место не присуждается»), порядок — правила дисциплины
  (`disciplines/psr.standings`, `disciplines/speleo.standings`).
- **Ранг** — `rank.qualification_rank`: баллы за разряды участников 1–6 мест, делитель по формату (связка — 2,
  группа — 4 или по числу участников); условие ЕВСК — `rank.evsk_participation_ok`.
- **Разряд** — `norms.achieved_norm`: процент от победителя (способ — в карточке) против таблицы норм по классу и
  рангу.
- **Порядок старта** влияет на места при равенстве — его берут из жеребьёвки (`start_list.ordered`).

Справочники ранга и норм выбираются по редакции норм в карточке (`Competition.norms_edition`).

## 10. Запуск, журнал, обновления, копии

- **`cli.cmd_web`**: полоска загрузки → проверка, не запущена ли уже программа (`/health`) → свободный порт с
  8765 → журнал → `create_app` → `uvicorn.Server`; в фоне — автокопии (`backup.auto`) и проверка обновлений
  (`Console`). Браузер открывается, когда сервер ответил.
- **Выключение** — кнопка «Выключить» (`/shutdown` → `app.state.shutdown`) или закрытие окна. Код выхода 75
  (`updates.RESTART`) — «перезапусти меня»: так файл запуска ставит новую версию.
- **Журнал** (`journal.py`): `Журнал/СТ-Секретарь.log` (по кругу 5 × 1 МБ), `сбои.log` (падения самого Python),
  метка `работает` (если при запуске она есть — прошлый раз программа закрылась нештатно, на главной
  предлагается скачать журнал). Паспортные данные в журнал не пишутся. Логгер — `logging.getLogger("st_secretary…")`.
- **Обновления** (`updates.py`, `console.py`, `web/pages/updates.py`): переносная версия скачивает архив своей
  системы с GitHub, сверяет sha256, распаковывает рядом как `program.new` и перезапускается; файл запуска меняет
  папки местами (прежняя — `program.old`). Запуск из исходников — `git merge --ff-only` и `uv sync`, затем
  перезапуск. Отключить проверку: `--no-update-check` или `ST_NO_UPDATE_CHECK=1`.
- **Резервные копии** (`backup.py`): zip папки соревнования в «Резервных копиях»; автоматически при запуске, если
  что-то менялось (хранится 10 автокопий); восстановление — всегда новой папкой. Сканы и паспорта в копию не входят.
- **Переносная версия** (`tools/build_portable.py`): архив с Python внутри; имена файлов выпуска без номера версии,
  чтобы ссылка «Скачать» в README всегда вела на последнюю. Выпуск на GitHub — только с согласия владельца
  проекта; текст — `docs/releases/<версия>.md`.
- **Пометка стадии** (`STAGE = "бета"` рядом с `__version__`, `version_label()`): видна в подвале страниц, окне
  программы, журнале, инструкции. В номер версии её не дописывать («0.4.0-beta» `parse_version` не поймёт —
  обновление не увидит); выпуск на GitHub называть «0.4.0 (бета)», но отметку pre-release НЕ ставить — иначе он
  пропадёт из `releases/latest`, а с ним ссылки «Скачать» и обновление кнопкой. К 1.0 — `STAGE = ""`.

Переменные окружения: `ST_PORTABLE` (запущена переносная версия), `ST_NO_BROWSER`, `ST_NO_UPDATE_CHECK`,
`ST_DEBUG` (показывать трассировку в командной строке), `ST_REF_DATA` (папка с настоящими протоколами для сверок).

## 12. Как сделать типичное изменение

**Новое поле в карточке соревнования**
1. Поле в `Competition` или `Zachet` (`competition.py`) со значением по умолчанию — старые карточки должны
   читаться; проверка значения — в `Competition.check()`.
2. Excel: запись и чтение — `importers/card_xlsx.py` (`write_card`, `load_card`; строки ищутся по тексту).
3. Форма: `web/forms.py` (`card_to_form`, `form_to_card`), шаблоны `card.html` и `card_view.html`.
4. Тест в `tests/test_card.py` и сохранение формы в `tests/test_web.py`.

**Новая проверка заявок (замечание)**
1. В `preapp.py` (`_entry` — участник, `_team_checks` — команда, `_cross_checks` — между заявками) добавьте
   `Issue(WARNING или ERROR, текст, why=почему, todo=что сделать, target=где исправить)`.
2. Если система исправила сама — `FIXED` с `before`/`after`: секретарь видит каждую правку.
3. Тест в `tests/test_preapp.py` на выдуманном участнике.

**Новая страница или действие**
1. Маршрут в подходящем модуле `web/pages/` (или новый модуль с `register(app, cx)` — добавить его в список в
   `web/app.py` и шаг в `web/steps.py`).
2. Шаблон `templates/<имя>.html`, начинается с `{% extends "base.html" %}`; передайте `**comp_ctx(f)` и
   `active="<шаг>"`.
3. POST → `redirect(with_done(адрес, "код"))`, текст для кода — в `web/common.flash`.
4. Расчёт — в ядро, не в страницу.
5. Тест в `tests/test_web.py`.

**Новый документ (Excel или Word)**
Функция `write_…(…, path)` в `exporters/`, шапка — из карточки (`comp.title`, `comp.dates_text`, подписи —
`Official.signature`), маршруты «сделать» (POST, открывает файл через `app.state.opener`) и «скачать» (GET) на
странице шага. Файл открыт в Excel — ловите `PermissionError` и показывайте сообщение.

**Новая дисциплина или профиль**
Код и формат — `reference/data/vrvs.toml`; допуск — `admission.toml` и `competition._PROFILE_BY_DISCIPLINE`;
расчёт — профиль в `time_run.profile` / `time_run.settings` (или `psr_run`, если результат — баллы этапов);
таблица штрафов — `penalties.default_key`; места — правила в `disciplines/`. Сверка с настоящим протоколом —
через `ST_REF_DATA`.

**Изменение страницы судьи**
Поле записи — в трёх местах: `rec()` в `judge.html`, `judge_sync.Record` (+ `from_json` с ограничением длины:
с телефона может прийти что угодно) и запись журнала в `judge_sync.merge`. Помните, что у судей в телефонах
могут остаться записи от прежней версии страницы — новые поля читайте с умолчанием. Проверка —
`tests/test_judge_sync.py` и вживую на телефоне (или в узком окне браузера) с выключенной сетью.

**Новый файл данных соревнования**
Константа имени и методы чтения/записи — в `CompFolder` (`web/store.py`) через `read_json` / `write_json`.
Решите, где ему место: в «данных» (переезжает с копией) или в «документах участников» (личные данные — только
этот компьютер). Добавьте его в схему в начале `web/store.py` и в раздел 5 этого файла. Проверьте, что
`backup.make` его забирает (он забирает всю папку соревнования).

**Крупное решение** — запись в `docs/decisions.md` (следующий номер, в конец): что решили и почему.

## 13. Соглашения

- **Язык.** Имена в коде — английские или транслит устоявшихся терминов (`zachet`, `zachety`, `psr`); тексты,
  docstring и комментарии — по-русски. Термины предметной области — как в Правилах (см. словарь).
- **Docstring у модуля** — что делает модуль и по каким пунктам Правил; у функции — одна строка «что на входе →
  что на выходе», с примером значения в «ёлочках»: `«12,5» → 12.5`.
- **Ссылки на источник.** Правило из документа — с пунктом: `(Правила, раздел 3, п. 8.18)`; изменение по листу
  правок — `(Правки, п. 25)`; по решению — `(решение 039)`.
- **Стиль** — ruff (правила и причины отключённых — в `pyproject.toml`), строка до 120 знаков (сообщения по-русски
  — до 130). Импорты внутри функций разрешены нарочно: быстрый запуск и необязательные библиотеки.
- **Данные пользователя не теряются**: ничего не удаляем без следа, не перезаписываем молча, не «исправляем»
  без отметки «Исправлено».
- **Классы данных** — `@dataclass`; хранение — простые словари JSON (`ensure_ascii=False, indent=1`).
- **Внешние запросы** — только проверка выпусков на GitHub; никаких данных соревнований наружу.

## 14. Ловушки

Вещи, на которых легко ошибиться при изменении. Оценка читаемости и план улучшений — в листе правок
(«Правки — лист 2», п. 38–39).

- **Формат состава зачёта — только константы** `rank.INDIVIDUAL / PAIR / GROUP / CREW` (`rank.RANK_FORMATS`).
  Состав своей дисциплины неофициальных соревнований (`Zachet.unit`: `person` / `pair` / `team`) переводится в них в
  `competition._RANK_FORMAT`; сравнивать `z.rank_format` со строкой «person» нельзя (так была ошибка п. 38).
- **Общая логика страниц — в `web/shared.py`** (раздел 7), не в `cx` и не в другой странице: раньше помощники жили
  в страницах и передавались через `cx`, и обращение к ним при подключении модуля зависело от порядка модулей в
  `web/app.py`. Нужна функция нескольким страницам — кладите её в `web/shared.py`.
- **Однофамильцы модулей:** `forms.py` (свои формы предзаявок) ≠ `web/forms.py` (форма карточки) ≠
  `web/pages/forms.py` (страницы своих форм); `rank.py` (ранг) ≠ `ranking.py` (места); `web/board.py` (сервер Wi-Fi)
  ≠ `web/pages/board.py` (страницы табло и судей). Снаряжение и сканы — в `web/pages/admission.py`.
- **«Один и тот же человек»** определяется по-разному: внутри заявки — ФИО без регистра и «ё»
  (`commission.person_key`), между командами и соревнованиями — ФИО + дата рождения (`commission.person_id`,
  `start_list.person_key`). Сравнивать ФИО, территории, представителей — только через `textclean.name_key` (без
  регистра, «ё», лишних пробелов); нужен ключ человека — возьмите существующую функцию, не пишите новую.
- **Время разбирают четыре функции** с разными форматами: `start_list.parse_hm` (время старта «10:00»),
  `time_run.parse_clock` / `parse_duration` (старт и финиш, отсечки), `stage_time.clock_seconds` (часы телефона).
- **Ключ команды — имя файла заявки.** Переименование файла отвязывает от команды баллы, отметки, жеребьёвку.
- **`Результаты_дистанции.json` — только под `run_lock`** (телефоны судей пишут в него из других запросов).
- **Пересчёт при каждом запросе.** Страница результатов пересчитывает заявки → допуск → состав → результат.
  Тяжёлое (чтение файлов) кешируйте по времени изменения файлов, как `Store.preapps`.
- **После `git pull` перезапустите работающую программу**: новые шаблоны со старым кодом дают «Что-то пошло не
  так». Обновление из окна программы делает это само.
- **Страница судьи открыта днями**: изменения в её скрипте дойдут до судьи, только когда он заново откроет ссылку.
