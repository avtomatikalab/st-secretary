# СТ-Секретарь — заметки для Claude

Программа для секретариата соревнований по спортивному туризму. Пользователи — секретари 50+, привыкшие к Excel;
программа работает без интернета. Общение, тексты интерфейса, коммиты и документация — по-русски.

## Окружение
- Python 3.12 и uv. Библиотеки: `uv sync --extra xls` (группа dev — pytest, ruff).
- Запуск: `uv run st-secretary web` → http://127.0.0.1:8765 (на другом порту: `--port 8766 --no-browser`).
- Перед каждым коммитом: `uv run pytest -q` и `uv run ruff check src tests tools`.
- На GitHub тесты идут сами после каждой отправки в main — на Windows, macOS и Linux (`.github/workflows/tests.yml`);
  результат: `gh run list --limit 3`.
- Программа должна работать на Windows, macOS и Linux (тесты и проверка архивов — на всех трёх в CI).
- Переносные версии для всех систем: `uv run python tools/build_portable.py` → `dist/` (имена файлов без версии —
  постоянные ссылки «Скачать» в README); проверить архив на его системе: `uv run python tools/check_portable.py
  dist/<архив>`. Установка на macOS/Linux одной командой — `tools/install.sh`. Инструкция секретаря со
  снимками экрана: `uv run --with websocket-client python tools/make_manual.py` (нужен Chrome или Edge; PDF
  делает Word — только на Windows).

## Работа с двух компьютеров
У разработчика две копии репозитория на разных компьютерах; обмен — только через GitHub.
- В начале работы: `git pull --rebase`.
- После каждого законченного этапа (тесты и ruff прошли): коммит и `git push`. Незапушенной работы на другом
  компьютере не будет.
- Одну и ту же копию репозитория в облачной папке, которую меняют два компьютера, не использовать: git портится.

## Правила
- Реальные данные соревнований (ФИО, даты рождения, паспорта, сканы) никогда не попадают в репозиторий: тесты —
  только на выдуманных и обезличенных данных (`tests/fixtures`), см. `.gitignore`.
- Документы участников хранятся вне облачных папок (`~/СТ-Секретарь — документы участников`).
- Выпуски на GitHub (Releases) и любые публикации — только с согласия владельца проекта.
- Решения и их причины — `docs/decisions.md` (новое решение — в конец, со следующим номером); план —
  `docs/roadmap.md`; текст выпуска — `docs/releases/<версия>.md`.
- Устройство: FastAPI + Jinja2, чистый JS без библиотек (всё работает без интернета); страницы — модули
  `src/st_secretary/web/pages/*.py` с `register(app, cx)`; после POST — переадресация с `?done=` (сообщение).
- Тексты для секретаря — простым языком, без технических слов; объяснять, что будет с данными.
