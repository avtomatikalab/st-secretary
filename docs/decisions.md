# Журнал решений

Кратко: что решили, почему. Новые решения — в конец.

### 001. Открытый код, AGPL-3.0 (28.09.2026)
Проект некоммерческий, код и инструкции — на GitHub. AGPL выбрана, чтобы изменённые версии,
работающие как сетевой сервис, тоже оставались открытыми.

### 002. Ноутбук секретариата — главная копия, офлайн прежде всего (28.09.2026)
На части соревнований интернета нет совсем. Всё, что нужно для проведения старта, работает на
ноутбуке без сети; облако — для табло и приёма данных, когда связь есть.

### 003. Хостинг в РФ, без зависимостей, требующих VPN (28.09.2026)
У многих судей нет VPN, у части операторов нет связи. Облачная часть размещается на российском
хостинге организатора; сервисы, недоступные без VPN, в обязательном контуре не используются.

### 004. Записи судей только добавляются (28.09.2026)
Исправление — новая запись со ссылкой на прежнюю. Нет конфликтов при слиянии данных с разных
устройств; полный след для разбора протестов.

### 005. ИИ не участвует в расчётах (28.09.2026)
Результаты, места, ранг, нормативы — детерминированно, по правилам, под тестами. ИИ допускается
только как помощник: разбор входящих заявок, подсказка судье пункта таблицы штрафов по описанию
нарушения. Провайдер ИИ — сменный модуль, доступный из РФ. Без интернета ИИ-функции недоступны,
остальное работает.

### 006. Точная арифметика (28.09.2026)
Время — в секундах, баллы и проценты — `Fraction`. Округление только при выводе. Процент от
результата победителя сравнивается с порогом нормы точно.

### 007. Спорные методики выбираются явно (28.09.2026)
Если документы допускают разные трактовки (например, «% от результата победителя» для балльных
дисциплин), система не выбирает сама: методика указывается в настройках соревнования и печатается
в примечании протокола. Уже реализована методика, по которой считал СЕКРЕТАРЬ_ST
(`POINTS_RELATIVE_TO_WINNER`); ответ коллегии судей ожидается.

### 008. Редакция разрядных норм выбирается в соревновании (28.09.2026)
Хранятся редакции 2022–2025 и 2026–2029 (последняя по решению организаторов считается
действующей; реквизиты приказа уточняются). Дополнительные нормы из Положения конкретного
соревнования — отдельная таблица соревнования.

### 009. Строки норм — по диапазону своего класса (28.09.2026)
В таблице норм для каждого класса дистанции отмечен свой диапазон строк ранга (они перекрываются):
1 кл — «менее 1»…«10 и более», 2 кл — до «40 и более», 3 кл — «20–24,9»…«160 и более»,
4 кл — «63–79»…«630 и более», 5–6 кл — «200–249»…«2400». Ранг ниже первой строки класса —
нормы не выполняются. Проверено по скану приказа (rank_appl_2022_2025.pdf, стр. 14).

### 010. Реальные данные не попадают в репозиторий (28.09.2026)
Тесты на реальных протоколах читают файлы из внешней папки (`ST_REF_DATA`) и пропускаются без неё.
В репозиторий входят только обезличенные наборы (команды «Команда 01…», разряды без ФИО).
`.gitignore` исключает xls/xlsx/doc/docx/pdf/csv.

### 011. Донаты — только для сервиса на серверах организатора (28.09.2026)
Приём пожертвований через самозанятого, только в облачной версии. Версия для ноутбука и
самостоятельное развёртывание бесплатны. В будущем возможна подписка.

### 012. Интерфейс — страница в браузере от сервера на ноутбуке (28.09.2026)
Секретарю неудобна командная строка. Программа запускается двойным щелчком (`СТ-Секретарь.bat`)
и открывается в браузере по адресу 127.0.0.1 — только на этом компьютере, потому что в заявках
персональные данные. FastAPI + шаблоны Jinja, немного JavaScript без библиотек: ничего не
собирается и не загружается из интернета. Когда судьям и табло понадобится Wi-Fi ноутбука
(этапы 2–3), доступ из локальной сети включается отдельно и осознанно.

### 013. Соревнование — папка с файлами Excel (28.09.2026)
Карточка, заявки и сводки лежат в папке соревнования как обычные файлы: их можно открыть без
программы, скопировать на флешку, передать коллеге. Карточка — тот же Excel, что и раньше; если её
изменили в Excel, пока была открыта страница, сохранение из браузера не затирает правки молча.
Кнопка «Убрать» не удаляет заявку, а переносит в «Предзаявки\Убранные». Протоколы этапов (этап 2)
потребуют базы данных с журналом записей — она появится там же, в папке соревнования.

### 014. Замечание объясняет себя; заявку можно исправить в программе (28.09.2026)
Секретарю мало знать, что «ошибка»: у каждого замечания уровня «Ошибка» и «Проверить» есть «почему»
(правило или откуда взято значение — «1995 год не високосный») и «что сделать» («уточните у
представителя», «вынесите на комиссию по допуску»), тест это проверяет. Заявку можно исправить в форме:
в поля подставлено то, как программа поняла заявку, а непонятое — как написано в файле. Сохранение
записывает обычный файл Excel в раскладке бланка, прежний файл (и при замене файла командой тоже)
переносится в «Предзаявки\Прежние версии» с датой и временем — ничего не удаляется. Если файл
изменился, пока форма была открыта, сохранение не затирает его молча.

### 015. Просмотр отдельно от правки; статус заявки и «проверено» (28.09.2026)
Карточка соревнования и карточка команды открываются для просмотра; правка — кнопкой «Редактировать»,
после сохранения снова открывается карточка. Так случайно ничего не меняется, а посмотреть заявку
можно, не разбираясь в форме.
У заявки три статуса. «Исправить» ставится сам, пока есть ошибки. «Проверить» ставится сам, когда
ошибок нет. «Проверено» ставит секретарь, и только когда ошибок нет; при этом все оставшиеся
«проверить» в заявке отмечаются проверенными. Статус, выставленный вручную, привязан к содержимому
файла (отпечаток SHA-1): если команда прислала новый файл или заявку исправили, статус снова
определяется сам — изменённую заявку нужно посмотреть заново, и на карточке сказано почему.
Отметка «проверено» ставится только у «проверить» (у ошибок — нет) и привязана к самому замечанию:
человек, поле и текст со значениями; если после правки замечание осталось тем же, отметка сохраняется.
Отметки хранятся в папке соревнования — «Отметки_предзаявок.json».
Дополнение (29.09.2026, по просьбе организаторов): если секретарь сохранил заявку в форме и в ней не
осталось ни ошибок, ни неотмеченных «проверить», «Проверено» ставится само — заявку только что смотрели
и правили. На карточке видно, что статус поставлен при сохранении; он снимается, если потом появится
ошибка или новое «проверить» или файл заменят. Загруженные файлы команд сами «Проверено» не получают.

### 016. Комиссия по допуску — поверх предзаявок, решения явно (29.09.2026)
Список участников комиссии — это предварительные заявки: ничего не набирается заново, а исправление
заявки (в том числе перезаявка) сразу видно на комиссии. Отметки комиссии хранятся отдельно
(«Комиссия_по_допуску.json») и привязаны к файлу заявки и ФИО участника — правка заявки не сбрасывает
отметки остальных. Участник допускается сам только при всех документах и без замечаний; всё прочее —
явное решение комиссии с основанием, которое попадает в протокол. Ошибки в заявке допуск блокируют:
их исправляют в заявке. Замечания о возрасте и допуске («по решению ГСК») решает комиссия, даже если
на предзаявках их отметили «проверено» — отметка секретаря не заменяет решение ГСК. Протокол — по образцу
из приложений к разделу 3 Правил; ФИО в нём нет, они — только в листе «Документы участников».

### 017. Сканы документов — только на ноутбуке и отдельно от данных соревнования (29.09.2026)
Сканы паспортов, полисов и справок хранятся в папке «СТ-Секретарь — документы участников» в профиле
пользователя (или там, куда укажет `--docs`), а не в папке соревнования: её копируют на флешку, передают
коллеге, а бывает — держат в облаке (Google Диск), куда паспорта попадать не должны. Показываются только
на этом компьютере (127.0.0.1), не кэшируются браузером; «Убрать» переносит файл в «Убранные», не удаляет.

### 018. Проверка снаряжения — перечень и баллы из Положения (29.09.2026)
По Правилам (часть 4, табл. 4): отсутствие личного предмета — 1 балл, группового — 5; «более 30 баллов
при проверке снаряжения» — снятие. Положение может установить своё (п. 6.2.2) — перечень, баллы и порог
задаются на соревнование; образец — перечень «ПСР КРСК 2025» (1 / 3 балла, порог 10). Если перечень
задан, команда без проверки снаряжения или с превышением порога не допускается комиссией.

### 019. Документы по итогам — из мест по зачётам, в Word и Excel (29.09.2026)
Результаты программа пока сама не считает (этап 2), поэтому места берутся из итогового протокола
СЕКРЕТАРЬ_ST (.xls) или вписываются вручную; хранятся в «Итоги.json». Даты рождения и пол — из заявок:
в протоколе их нет, а без даты рождения выписку на разряд не примут (ЕВСК, п. 67.8.2) — такая ячейка
подсвечена. Документы собираются в Word и Excel, а не в PDF: перед печатью их почти всегда правят.
ФИО в справках и название соревнования в дипломах склоняются по окончаниям; незнакомое слово остаётся
как есть, чтобы не исказить. Отчёт главного судьи считает участников по решениям комиссии по допуску
(если комиссии не было — всех заявившихся). Субъект РФ программа по территории не определяет —
в справке стоят территории команд, их проверяет секретарь.

### 020. Договоры, акты, табель — из одних отметок дней; паспорта — только на ноутбуке (29.09.2026)
Табель, договор и акт строятся из одних и тех же отметок «р» по дням, поэтому дни и суммы в них совпадают
сами: в 2025 г. в табеле у двух человек было 3 отметки при оплате 4 дней, а в договоре главного судьи срок
«19–21 сентября» при акте «18–22 сентября, 5 дн.». Срок в договоре — с первого по последний отмеченный день
(как в акте). В табеле-наряде дни и суммы — формулами Excel, чтобы правка отметки в Excel пересчитывала их.
Ставки — по должности и категории, задаются на соревнование (образец — ставки 2025 г.). Форма договора —
у заказчика своя (у МАУ «ЦСК» их четыре: главный судья, судьи, комендант, рабочие), поэтому договор
собирается из шаблона Word с полями `{{…}}`: общий, для должности или встроенный. Паспорт, ИНН, СНИЛС и счёт —
в файле в папке документов участников (не в облаке, не в папке соревнования), общий на все соревнования;
туда же сохраняются договоры и табель. ИНН, СНИЛС и счёт по БИК проверяются по контрольным цифрам — опечатка
в реквизитах ловится до подписи, а не в бухгалтерии.

### 021. Сверка — по готовым файлам, замечания с цитатой; исправляет человек (29.09.2026)
Документы программы между собой согласованы по построению (всё из карточки и одних данных), но их правят
в Word и Excel, а часть документов приходит со стороны: протоколы СЕКРЕТАРЬ_ST, договоры и акты заказчика,
табель. Поэтому сверка читает сами файлы (Word, Excel, PDF с текстом), а не данные программы, и ищет то, что
в папке 2025 г. нашлось вручную: даты прошлого года, чужой код ВРВС, «комбинированые», отметки ≠ дням
к оплате, срок договора ≠ сроку акта. Каждое замечание — с цитатой из документа; программа ничего не правит
сама: исправление в чужом документе (договор заказчика) — решение человека. Присланные на сверку файлы не
сохраняются — в договорах паспортные данные. Сверка не мешает работе: она не блокирует печать и выгрузку.

### 022. ПСР в программе: вводятся итоговые баллы этапов; протоколы по п. 8.17–8.18; табло — отдельно (30.09.2026)
Секретарь вносит итоговые баллы этапов из протоколов судей — так же, как в «Протокол_группа» СЕКРЕТАРЬ_ST:
формула перевода времени в ВШ между НВ и КВ не определена (вопрос 11), а судьи этапов считают баллы сами.
Переход плавный: этапы и баллы переносятся из рабочей книги СЕКРЕТАРЬ_ST. Таблица ввода не перерисовывается
при сохранении — обновляются только суммы и места, чтобы при быстром наборе ничего не терялось; команда без
единого балла места не получает. Время публикации предварительного протокола начинает час на протесты
(п. 8.17); официальный протокол — только после решений по всем протестам и если после публикации ничего не
менялось; утверждение раньше часа — с подтверждением (решение главного судьи). Официальные результаты сразу
передаются в награждение. Табло — отдельный сервер только для чтения на всех адресах ноутбука: основная
программа с заявками и документами по-прежнему открывается только на 127.0.0.1; табло включается кнопкой
и только для выбранных соревнований.

### 023. Телефоны судей — страница в раздаче по Wi-Fi, записи в телефоне, слияние без затирания (30.09.2026)
Отдельное приложение ставить не нужно: судья открывает ссылку этапа (QR) в браузере телефона, пока он в Wi-Fi
ноутбука. Без HTTPS браузер не даёт странице работать полностью офлайн (service worker), а сертификат на
поляне — лишняя сложность для людей 50+; поэтому страница загружается на базе и дальше работает сама, всё
хранит в памяти телефона (localStorage) и отправляет, когда есть связь. Судья вносит итоговый балл этапа —
как и секретарь (решение 022). Ссылка — случайный код этапа: с ним можно писать только свой этап, новая ссылка
отменяет прежнюю. Таблица секретаря главнее: присланное заполняет пустые клетки и заменяет прежнее
присланное, но не исправления секретаря — расхождение показывается человеку. Снятие с этапа в ПСР — не снятие
с дистанции, поэтому статус команды не меняется, а секретарь видит отметку. Время — по часам телефона.

### 024. Спелео и пешеходные — один расчёт «по времени»; SPORTident — по чипу команды (30.09.2026)
У спелео и пешеходных дистанций в штрафной системе одна формула: время на дистанции (финиш − старт − отсечки)
плюс штрафные баллы × 15 или 30 с. Поэтому один расчёт и одна страница; снятие с этапа — буква «с» в клетке
этапа, как его пишут в протоколах; со снятиями — места после прошедших полностью, разряд им не присваивается
(дистанция пройдена не полностью — вопрос 33). Ошибка во времени старта, финиша или отсечек лишает места до
исправления, а не считается нулём. Время суток хранится только как «чч:мм:сс»: «12:10» иначе прочиталось бы
как полдень. SPORTident: читается весь файл SI Reader (СЕКРЕТАРЬ_ST берёт только последнюю строку и для групп
импорт не делает); чип закрепляется за командой — колонка «Чип» или номер чипа из заявки; перечитанный чип —
последнее считывание; время чипа заменяет вписанное вручную, и об этом сообщается. Учёт судейской практики —
по данным всех соревнований в программе; баллы по таблицам приказа № 1101 не считаются, пока нет точной таблицы
(PDF приказа при извлечении перемешивается).

### 025. Жеребьёвка — по зачётам, с записью жребия; порядок старта один для всей программы (30.09.2026)
Правила (раздел 3, п. 8.4) требуют раздельной жеребьёвки для возрастных групп, мужчин и женщин — в программе
зачёт и есть такая группа, поэтому жеребьёвка — по зачётам. Компьютерная жеребьёвка допускается Правилами;
программа записывает время и шестизначное число жребия, при том же числе и составе порядок повторяется —
жеребьёвку можно проверить. Часто номера тянут на совещании с представителями — тогда порядок вносится вручную;
перестановка после компьютерной жеребьёвки помечается в протоколе («порядок изменён вручную»). Групповая
жеребьёвка — по рангу состава, как «Ранг» в стартовом протоколе СЕКРЕТАРЬ_ST; сильные по умолчанию стартуют
последними. Время старта — первый старт плюс интервал, правка отдельной команды хранится отдельно. Команды,
допущенные после жеребьёвки, ставятся в конец с предупреждением, а не перемешивают опубликованный порядок.
Порядок старта из жеребьёвки — единственный: по нему идут таблица результатов (равенство «выше стартовавший
раньше»), страницы судей и табло; в дисциплинах по времени время из протокола — время старта команды, если
старт не вписан (спелео, часть 8, п. 1.5.5). Публикация, как у протокола результатов, фиксирует отпечаток —
изменения после неё видны; с неё идёт час на протесты по допуску (п. 8.17).

### 026. Установка — переносной архив с официальным Python, а не .exe-упаковщик (30.09.2026)
Секретарю нужно «распаковал — дважды щёлкнул — работает», без uv и без интернета при первом запуске.
Упаковщики в один .exe (PyInstaller и подобные) распаковывают себя при каждом запуске и часто ложно
определяются антивирусами как вирус; установщик (Inno Setup) требует прав администратора. Поэтому — архив:
официальная сборка Python «embeddable» с python.org (подписана PSF), библиотеки по uv.lock — те же версии, что
в тестах, файл запуска .bat. Модули скомпилированы заранее с проверкой по хешу «без сверки»: программа ничего
не пишет в свою папку, и её можно распаковать даже в папку облака. Пути в .bat — латиницей (работает при любой
кодовой странице консоли), сообщения — в CP866. Данные — в папке «данные» рядом, её в архиве нет, поэтому
обновление («удалить program, распаковать новый архив») её не трогает. Сборка проверяется прогоном всех тестов
на распакованном архиве.

### 027. Инструкция — из программы, на учебном соревновании (30.09.2026)
Людям 50+ нужна бумажная (или PDF) инструкция со снимками экрана, но снимки, сделанные вручную, устаревают с первым
же изменением интерфейса. Поэтому инструкцию собирает скрипт: создаёт учебное соревнование, проходит его шаг за
шагом через саму программу и снимает страницы браузером без окна (Chrome/Edge через DevTools — снимается ровно
нужный блок, без меню). Реальных данных в инструкции нет — только выдуманные. То же учебное соревнование доступно
секретарю кнопкой: тренироваться на нём, а не на настоящих заявках. Ошибки в учебных заявках — те, что встречались
в реальных (несуществующая дата, нет женщины в команде, возраст, один человек в двух командах, «кмс» и ФИО
прописными), чтобы тренировка была на настоящих ситуациях.

### 028. Резервные копии — zip папки соревнования, автоматически при запуске, восстановление без затирания (30.09.2026)
Данные соревнования — файлы в одной папке, поэтому копия — просто архив этой папки: её можно открыть без программы.
Люди не делают копии сами, поэтому программа делает их при каждом запуске — только если что-то менялось, и хранит
10 последних автоматических (ручные не удаляет). Копии — в папке «Резервные копии» рядом с «данными», а не внутри:
иначе они выглядели бы соревнованиями и попадали бы в собственные копии. Восстановление никогда не пишет поверх
существующей папки — соревнование ложится рядом с пометкой «восстановлено»: ошибка при восстановлении не должна
стоить текущих данных. Архив проверяется, прежде чем что-то распаковать: одна папка, карточка внутри, никаких путей
наружу. Паспорта и сканы в копию не входят (они вне папки соревнования) — копию можно спокойно нести на флешке.

### 029. Все дисциплины со стартом и финишем — один расчёт с профилями; кто получает место — по формату ВРВС (30.09.2026)
Спелео, пешеходные, северная ходьба и горные устроены одинаково: старт, финиш, отсечки, нарушения по этапам. Разница —
в том, во что превращаются нарушения и снятия: секунды за балл (спелео 15/30 с, пешеходные 15/30 с по типу дистанции,
северная ходьба 15 с), штрафное время (пешеходные, СХ), снятие с дистанции или ОКВ за снятие (пешеходные, п. 6.2.8),
аннулирование или ОКВ за красную карточку (СХ, п. 10.4.4), баллы за минуту у горных (часть 2, п. 6.1.4). Поэтому
один расчёт с профилем дисциплины, а не четыре; выбор, который Правила оставляют Условиям, — настройка зачёта.
Статус, поставленный по правилам (снят, аннулирован, превышено КВ), показывается рядом с выбранным вручную и не
«застревает» после исправления данных. Кто получает место, определяет формат ранга дисциплины в ВРВС: группа — вся
команда (или каждая группа, если их несколько), связка — по отметкам связок в заявке, личная — каждый спортсмен
(номер «команда.номер в команде», как вариант 1 нумерации СЕКРЕТАРЬ_ST). Ключ группы — прежний (файл заявки), чтобы
внесённые баллы не потерялись. ЕВСК п. 25.4.2 (не менее 6 участников при баллах, начисляемых судьями) применяется ко
всем штрафным системам, включая спелео, — раньше спелео ошибочно считалось по п. 25.4.1 (не менее 3).

### 030. Страницы — модулями по шагам работы; правила проверки стиля — в проекте (30.09.2026)
Файл программы в браузере вырос до 2400 строк: одна функция создавала приложение и все страницы. Теперь
`web/app.py` — только создание приложения, общие помощники (страница, папка соревнования, карточка) и ошибки,
а страницы — модули `web/pages/` по шагам работы секретариата. Код перенесён дословно (скриптом по синтаксическому
дереву), поэтому поведение не менялось — это проверили все тесты. Помощники, которые нужны нескольким страницам
(допуск команды, расчёт зачёта, стартовый протокол), страница кладёт в общий контекст `cx`, другие берут оттуда.
Правила ruff записаны в `pyproject.toml` явно: новая версия ruff сама включала десятки правил, и «замечания»
появлялись без изменений кода. Отключено с пояснением то, что противоречит устройству программы: время по часам
ноутбука без часовых поясов (DTZ не включён), кириллица и типографика в текстах, отложенные импорты для быстрого
запуска; длина строки — до 130 знаков, чтобы не рвать сообщения посередине фразы. Остальное исправлено — в том
числе функции в циклах, которые держали переменную цикла по ссылке.

### 031. Баллы практики — по Excel-таблице ФСТР, условия — числами рядом с текстом (30.09.2026)
PDF приказа № 1101 при извлечении перемешивает строки таблицы, а на сайте ФСТР есть та же таблица в Excel. Её
переносит в справочник скрипт `tools/import_1101.py`: объединённые ячейки разворачиваются (у «Главного секретаря» —
баллы «Главного судьи» из той же строки таблицы), числа не переписываются руками. Числовые условия (сумма баллов,
соревнований, в составе ГСК, «не ниже» статуса) записаны в скрипте рядом с текстом из таблицы, текст показывается
судье целиком. Засчитываются только соревнования с оценкой «хорошо» и «отлично» (примечание 3), без оценки — отдельно.
Период считается до сегодняшнего дня: дату приказа о категории программа не знает, это видно в подсказке. Статус
соревнования — из вида и уровня в карточке; межрегиональные кубки и «другие» межрегиональные в таблице не названы —
баллов по ним программа не даёт (вопрос 47).

### 032. Обновления — с GitHub Releases, ставит сам «СТ-Секретарь.bat» (30.09.2026)
Выпуски публикуются на GitHub (архив `st-secretary-<версия>-windows.zip` латиницей — GitHub заменяет в именах файлов
кириллицу; внутри архива названия прежние). При запуске программа в фоне спрашивает `api.github.com/…/releases/latest`
(5 секунд на ответ, только запрос — без данных; без интернета — молча ничего) и, если версия новее, показывает
сообщение на главной. Переносная версия обновляется кнопкой: резервная копия изменившихся соревнований → архив
скачивается только из выпусков проекта и сверяется с sha256, который GitHub публикует у каждого файла выпуска →
папка `program` из архива распаковывается как `program.new`, в ней сверяется номер версии → программа выходит с
кодом 75, а `.bat` переименовывает `program` → `program.old`, `program.new` → `program` и запускает снова
(страница сама ждёт новую версию по `/health`). Заменять папку должен `.bat`: работающий python.exe не может
заменить сам себя. Сам `.bat` обновление не меняет — его построчно читает работающая консоль; если он когда-нибудь
изменится, об этом скажет текст выпуска (распаковать архив вручную). Из исходников (git) — только ссылка на выпуск.
Отключить проверку: `--no-update-check` или `ST_NO_UPDATE_CHECK=1`.

### 033. Windows, macOS, Linux — переносные архивы для всех, собираются на одном компьютере (30.09.2026)
Программа — браузерный интерфейс на Python, поэтому работает везде; нужна лишь поставка «распаковал — запустил».
Windows — как раньше (Python embeddable с python.org, .zip, «СТ-Секретарь.bat»; окончание имени `-windows.zip`
не меняется — его ищет уже выпущенная 0.1.0). macOS (Apple и Intel) и Linux (x86_64) — Python из
python-build-standalone (его же ставит uv; версия и sha256 закреплены в сборщике), архив .tar.gz: в нём
сохраняются права на запуск и ссылки (python3 → python3.12), чего нет в .zip. Файлы Python переписываются в
итоговый архив без распаковки на диск, а библиотеки для чужой системы uv ставит по её меткам (`--python-platform`),
поэтому все четыре архива собираются на одном компьютере. Файл запуска — один bash-скрипт (`.command` для Finder,
`.sh` для Linux) с тем же циклом обновления, что у .bat (код 75, program.new → program, прежняя — program.old);
на macOS он снимает «карантин» с папки программы, иначе система не даст запустить Python из архива, скачанного
браузером. У программы нет подписи Apple (платная), поэтому архив из браузера при первом запуске требует «Всё равно
открыть» в настройках; установка одной командой (`tools/install.sh`: curl → последний выпуск для этой системы,
сверка sha256 из GitHub, `~/СТ-Секретарь`, ярлык, запуск) обходится без этого — файлы, скачанные curl, macOS не
помечает. Проверка: тесты на трёх системах и `tools/check_portable.py` в GitHub Actions — архив для системы
runner'а распаковывается, ставит сам себя как обновление, запускается файлом запуска, открывает страницы,
выключается кнопкой; на macOS и Linux — ещё установка и обновление через install.sh. Тексты интерфейса («чёрное
окно», «СТ-Секретарь.bat») — по системе (`system.py`).

### 034. Файлы выпуска — без номера версии, «Скачать» — первым разделом README (30.09.2026)
Судьи ставили программу из исходного кода (Code → Download ZIP, «СТ-Секретарь.bat» из репозитория) и упирались в
uv, PowerShell и нужную версию Python, хотя готовый архив ничего этого не требует. Теперь файлы выпуска называются
без версии (`st-secretary-windows.zip`, `st-secretary-macos-arm64.tar.gz`, …, `st-secretary-manual.pdf`), и
ссылка `…/releases/latest/download/<имя>` всегда скачивает последнюю версию в один щелчок — такие ссылки стоят
первым разделом README («Скачать») и их можно рассылать. Номер версии — в названии выпуска, в программе и в
«Прочтите меня». Обновление не ломается: 0.1.0 ищет архив по окончанию `-windows.zip`. Файл запуска из исходников
без uv больше не отсылает к установке uv, а говорит, что это исходный код, и открывает страницу скачивания.
